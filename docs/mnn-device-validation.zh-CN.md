# MNN 群聊总结真机验证记录

本文件是可复制填写的验收模板，对应 [实施计划 S0](mnn-group-summary-roadmap.zh-CN.md)。**当前没有真机测量结果，以下项目均为“未测”；不代表 APK 已在设备运行、模型质量达标或性能通过。** 使用方式见 [功能说明](mnn-group-summary.zh-CN.md)，合成数据与预期事实见 [评测样例说明](../tests/ai-summary/fixtures/README.md)。

结构数据校验只能证明样例格式及标注符合规则；JVM 测试验证模拟环境下的客户端逻辑；CI 构建、签名和对齐检查验证 APK 产物。三者均不能证明真机安装、MNN 连通、后台行为、推理性能或摘要事实正确。分别记录证据，不相互替代。

## 2. 使用合成消息复现

1. 按 [评测样例说明](../tests/ai-summary/fixtures/README.md) 选择案例，记录样例版本/commit、案例 ID 和对应预期事实。只用合成内容，在测试者自有的隔离测试群/Topic 中手动准备数据，不把真实聊天混入样本。
2. 分别准备 **20、100、300 条有效短文字消息**和长文本集合。需要填充时使用固定的合成闲聊，并保存组成清单及顺序；不要把参考答案发送进群。记录条数、总字符数、最长消息字符数和发送者/回复关系。Telegram 消息长度限制可能导致拆条，以实际发送后的有效条数为准。
3. 每轮使用独立测试范围，确认消息均已发送成功。记录样例消息 ID 与 Telegram 原消息 ID 的对应关系；实际 `[mN]` 编号以本次选取顺序为准，不能直接拿样例 ID 当客户端引用。普通群和具体 Topic 至少各执行一次，并在相邻 Topic 放置可识别的合成干扰消息以检查范围隔离。
4. 在 MNN Chat 加载记录中的模型、启动 API，再切换到 Telegram。使用该 APK 已提供的连接测试功能（如有）执行不含聊天内容的短请求；否则直接执行 20 条样例总结。记录实际鉴权和回复，不能仅凭 `/models` 可访问判定 Chat 请求通过。
5. 选择最近 N 条并开始总结。保存实际纳入数量/范围、开始与完成时刻、结果和引用检查证据；检查点击引用能定位原消息，包括当前未加载到屏幕的消息。不要将摘要自动发送回群。
6. 对每个基线场景记录一次明确标注的模型初载后首轮，再在相同条件下至少重复 3 轮。明确计时是否包含模型加载；不把“已加载模型后的首次请求”称为模型冷启动。变更后台状态、参数或模型后另起一行。
7. 按下表单独执行生命周期和失败用例，再逐条核对预期事实。只保留必要的合成数据证据；日志不得包含 API Key。任何不可测指标均填“未测 + 原因”，不得用估算值补齐实测。

长文本至少包含一个可完成的分块/合并案例，并将关键决定、否定或任务转交放在跨块位置；另外准备超出已确认客户端输入预算的案例，验证明确失败、没有静默截断。字符数不等于 token 数；服务端上下文超限要单独测试，不能用客户端预算错误代替。

## 4. 逐轮性能记录

统一从点击“开始总结”计时：加载耗时为历史读取结束减开始；首结果为首次可见摘要减开始；总耗时为最终完成/失败/取消减开始。普通模式的首结果通常接近总耗时；流式模式另记录首次可见正文，**两者均不能直接当作服务端纯推理首 token 延迟**。若缺少阶段埋点，则该阶段填写“未测”，不要从动画或总耗时反推。模型耗时应明确是各 HTTP 请求耗时之和还是服务端纯推理时间。

## 5. 成功、失败与质量判定

- **功能成功**：按请求范围读取消息，完成本轮摘要，界面无崩溃/ANR，引用能定位正确原文，范围说明与实际覆盖一致。成功不自动代表事实正确或性能达标。
- **质量通过**：逐项匹配案例标注的关键事实和支持消息；区分建议/决定、否定/改口、争议/共识、任务转交，保留跨段关系，无结论或无待办时不编造。不能只凭输出包含引用或三个标题判定。
- **预期错误通过**：故障条件确实发生，客户端明确失败/部分范围并可恢复；这不是“总结成功”。HTTP 200 也可能携带服务端错误。
- **取消通过**：客户端取消行为符合 L04–L06；另列服务端停止推理的实测结论，不合并为一个通过项。
- **失败**：崩溃/ANR、静默漏掉范围、错误跳转、账号/Topic 混用、错误被当作摘要，或事实遗漏/幻觉等不满足对应标准。注明是功能、质量还是性能失败。
- **未测**：没有执行、缺少设备/仪器、无法构造或证据不足；附原因。部分范围结果须标注限制，不能用于证明完整范围总结通过。

| 待填 | 待填 | 未测 | 未测 | 未测 / 未测 | 待填 |

按案例保留逐项判断；至少单独列出关键事实覆盖数/预期数、无依据事实数、引用定位正确数/检查数。错误引用与引用正确但不支持结论是两种不同问题。模型存在随机性，同一案例多轮结果不一致时保留所有失败样本。
