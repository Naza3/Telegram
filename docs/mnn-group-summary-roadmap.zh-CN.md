# Telegram 本机 AI 群聊总结实施计划

本计划用于逐步完善 Telegram 安卓客户端中的 MNN 群聊总结，目标是让用户快速补齐群聊进度、按自己的关注点总结。S0–S9 记录现有功能及验收，S10–S14 已进入首轮代码集成，覆盖独立总结中心、统一界面、编辑后发回来源群、发送记录和有界后台任务；未完成的设计项及设备验收继续保留。新直接总结不要求原消息跳转，旧历史及独立追问的核验能力保持各自约定。

更新日期：2026-10-04。本文同时记录后续实施计划和已完成的代码验证；任务状态以勾选和验收记录为准，代码通过不代表真机已经验收。后续每次选择一个阶段或任务编号执行，完成后在本文记录证据和剩余问题。

## S1 用 Prompt 引导总结方向

规则版本 6 将写作任务交给用户手动填写，不再自动内置三栏、字数、语言、模板或本人关注要求。Prompt 决定如何处理消息，客户端筛选决定发送哪些消息；独立追问继续使用自己的来源与引用规则。

### 用户可配置的内容

| 配置 | 当前方案 |
| --- | --- |
| 核心总结要求 | 多行手动输入，初始为空；沿用以前保存的自定义文字，可清空并保存 |
| 栏目、语言与长度 | 由手动要求决定，不自动附加三栏、220／440 字目标或旧模板 |
| 保存范围 | 默认仅本次面板；可保存为该群／Topic 的偏好或当前账号默认 |
| 优先级 | 本次覆盖 → 当前群／Topic 偏好 → 当前账号默认 → 空值 |
| 长度限制 | 最多 1000 个 Unicode 字符，预算按规范化后的 UTF-16 长度只计一次，超限拒绝 |
| 空值 | 可保存，但直接总结在历史读取／API 调用前拦截；导出、连接测试独立可用 |

> 仅依据原文，用“风险”和“仍需确认”两栏整理发布安排。区分建议和已确认事项；不要补造结论、负责人或日期。使用中文。

“忽略闲聊”“关注某人”须写入核心要求才成为写作要求；真正排除消息仍由 S6 的客户端筛选完成。
